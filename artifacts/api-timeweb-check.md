## Сопоставление Flutter ↔ FastAPI

| Метод | Полный путь | Авторизация | Тело / параметры | Успешный ответ | Основные ошибки |
|---|---|---|---|---|---|
| POST | `/api/v1/auth/trusted-devices` | Bearer | `device_name`, 2–120 символов | `201`, устройство и однократно показанный `refresh_token` | `401`, `403 password_change_required/account_inactive/school_inactive`, `422` |
| POST | `/api/v1/auth/trusted-devices/refresh` | refresh-token, без Bearer | `refresh_token`, 40–256 символов | `200`, новый access-token, ротированный refresh-token, пользователь | `401 trusted_session_invalid/trusted_session_expired`, `403` |
| POST | `/api/v1/auth/trusted-devices/revoke-token` | refresh-token, без Bearer | `refresh_token` | `200`, идемпотентный отзыв | `422` |
| GET | `/api/v1/auth/trusted-devices` | Bearer | — | `200`, список активных устройств | `401`, `403` |
| DELETE | `/api/v1/auth/trusted-devices/{id}` | Bearer | целочисленный `id` | `200` | `401`, `404` |

- Retrofit использует те же пути относительно base URL `/api/v1`.
- Имена JSON совпадают: `refresh_token`, `trusted_device_id`, `expires_at`,
  `last_used_at`, `created_at`.
- Refresh-token имеет не менее 256 бит случайности, хранится в БД только как
  SHA-256 и вращается при каждом успешном обновлении.
- PIN состоит из четырёх цифр, не отправляется на API и хранится на Android
  только как производный хеш с отдельной солью в secure storage.
- После пяти локальных ошибок доверенная сессия удаляется с телефона; требуется
  обычный логин и пароль.
- Отключение пользователя/школы и обязательная смена пароля проверяются сервером
  при каждом refresh.
- Web не предлагает PIN и продолжает использовать обычный вход.

## Конфигурация и миграции

- Добавлена миграция `009_trusted_device_sessions`, следующая после
  `008_superadmin_password_recovery`.
- `.env.example` содержит `TRUSTED_DEVICE_EXPIRE_DAYS=30`, без секретов.
- Обязательные `DATABASE_URL`, `SECRET_KEY`, CORS и access-token настройки
  сохранены.
- Публичных HTTP-маршрутов восстановления суперадминистратора нет. Сброс
  выполняется только интерактивной CLI-командой в терминале сервера.
- `entrypoint.sh` проверяет БД, выполняет `alembic upgrade head` и запускает
  `uvicorn app.main:app --host 0.0.0.0 --port 8080`.
- `/health` и `/ready` не изменены.

## Ручной чек-лист после авто-деплоя

1. Убедиться, что миграция `009_trusted_device_sessions` выполнена.
2. Проверить `/ready` и вход каждой ролью.
3. На Android войти логином и паролем, создать PIN и перезапустить приложение.
4. Убедиться, что правильный PIN восстанавливает роль, а пять неверных попыток
   возвращают обычную форму входа.
5. Отозвать устройство в профиле и проверить повторный запрос логина и пароля.
6. На ширине телефона проверить окно выбора учеников и кнопку
   «Добавить ученика» над нижней навигацией.
7. Открыть `https://gbousecurity.ru/about/` и проверить статическую страницу.

## Публикация Android

Текущий локальный APK подписан отладочным ключом, потому что
`android/key.properties` отсутствует. Для первой публикации в RuStore нужно
создать постоянный release-ключ, сохранить резервную копию вне Git и далее
подписывать все обновления только им.
