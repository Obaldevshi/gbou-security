# E04 — Ролевая отложенная загрузка Flutter Web

## Цель

Показать рабочую форму входа за 5–10 секунд при холодном открытии и не
загружать административные функции пользователям, которым они недоступны.

## Границы итерации

- стартовый модуль: splash, вход, восстановление сессии, обязательная смена
  пароля и общие компоненты темы;
- модуль учителя: создание заявки, активные заявки, история, ученики, профиль;
- модуль охраны: очередь заявок и профиль;
- административный модуль: школы, пользователи, классы, массовый импорт,
  аудит, отчёты и профиль;
- выбор модуля выполняется после восстановления сессии по `UserRole`;
- API, база данных, права доступа и мобильная сборка не меняются.

## Реализация Flutter Web

1. Разделить единый `app_router.dart` на стартовый роутер и три фабрики
   ролевых маршрутов.
2. Подключить ролевые фабрики через deferred imports только для web; mobile
   продолжает использовать обычные импорты.
3. Показывать русскую компактную страницу загрузки выбранного кабинета после
   успешного входа.
4. Изолировать `excel` и `file_picker` внутри административного модуля, чтобы
   они отсутствовали в стартовом пакете и пакетах учителя/охраны.
5. Сохранить существующие URL, redirect-правила GoRouter и проверки ролей.

## Хостинг

- подключить TimeWeb CDN к домену frontend-приложения;
- кэшировать версионированные JS/Wasm-файлы длительно, а `index.html` — коротко;
- сохранить текущие gzip-артефакты и проверить, отдаёт ли CDN корректный
  `Content-Encoding`; если да, удалить клиентскую распаковку;
- установить месячный лимит CDN-трафика.

## Критерии приёмки

- холодное открытие формы входа: целевой p75 не более 10 секунд;
- повторное открытие формы входа: не более 3 секунд;
- учитель и охранник не скачивают административный пакет;
- административный пакет начинает загружаться только после определения роли;
- прямые ссылки и восстановление сессии открывают правильный кабинет;
- поведение mobile не изменилось;
- все четыре роли проходят вход и выход без ошибок браузера.

## Проверки

- сравнить размеры стартового и ролевых чанков;
- проверить Chrome/Edge и безопасный JS fallback для Safari/Firefox;
- проверить вход каждой ролью, обновление deep link и истечение сессии;
- замерить cold/warm load на production до и после CDN.

## Реализовано в исходном коде

- `AppRoutes` вынесен из общего роутера, поэтому ролевые страницы больше не
  образуют обратную зависимость на стартовый модуль;
- добавлены четыре независимых модуля: учитель, охрана, администратор школы и
  главный администратор;
- web использует deferred imports, mobile — обычные импорты с теми же
  фабриками страниц;
- стартовый DI содержит только инфраструктуру, авторизацию и обязательную
  смену пароля; ролевые repositories, use cases и cubits регистрируются после
  загрузки соответствующего кабинета;
- mock-конфигурация исключена из production bootstrap;
- для загрузки ролевого чанка добавлен русский экран ожидания и повтор;
- генератор gzip теперь включает `*.part.js`, service worker умеет отдавать
  сжатые deferred-чанки, версия web-кэша поднята до `1.1.0-7`.

## Результат сборки

- Flutter analyzer: без замечаний;
- production web build: успешно;
- создано 10 deferred `*.part.js` и 10 соответствующих gzip-файлов;
- `main.dart.js`: 3 524 169 байт, gzip: 989 642 байта;
- CanvasKit оставлен на домене приложения для CDN-кеширования;
- браузерная проверка четырёх реальных учётных записей выполняется после
  публикации новой сборки.
