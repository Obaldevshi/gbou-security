# E15 — Быстрый вход по PIN на доверенном Android-устройстве

Статус: реализовано, ожидает публикации миграции и Android-сборки
Приоритет: пользователь поручил выполнить после отказа от встроенного обновления APK

## Цель и границы

После первого полного входа пользователь Android может задать четыре цифры и в
следующий раз разблокировать приложение без повторного ввода логина и пароля.
PIN не является серверным паролем, не работает на другом телефоне и не даёт
доступа при отключённой учётной записи или школе. Web остаётся с обычным входом.

## Сущность `trusted_device_sessions`

| Поле | Тип / ограничение | Назначение |
|---|---|---|
| `id` | integer PK | Идентификатор доверенного устройства |
| `user_id` | FK users, cascade, index | Владелец |
| `name` | varchar(120) | Понятное имя, например «Android-приложение» |
| `token_hash` | varchar(64), unique, index | SHA-256 случайного refresh-token; сам токен в БД не хранится |
| `expires_at` | timezone datetime, index | Срок доверия, по умолчанию 30 дней |
| `last_used_at` | timezone datetime nullable | Последнее успешное обновление |
| `revoked_at` | timezone datetime nullable | Момент отзыва |
| timestamps | inherited | Создание/изменение |

Пользователь имеет несколько сессий. Токен содержит не менее 256 бит случайности,
ротируется при каждом refresh, а старое значение перестаёт работать.

## API

Все ответы используют существующий `SuccessResponse`.

| Метод и путь | Авторизация | Запрос | Успех | Ошибки |
|---|---|---|---|---|
| `POST /api/v1/auth/trusted-devices` | Bearer | `{device_name}` | `201`, id/name/expires_at/refresh_token | 403 временный пароль/неактивность, 422 |
| `POST /api/v1/auth/trusted-devices/refresh` | refresh-token в body | `{refresh_token}` | `200`, новый access + новый refresh + user | 401 недействителен/истёк/отозван, 403 пользователь/школа отключены |
| `POST /api/v1/auth/trusted-devices/revoke-token` | refresh-token в body | `{refresh_token}` | `200` | всегда идемпотентно |
| `GET /api/v1/auth/trusted-devices` | Bearer | — | список текущего пользователя | 401/403 |
| `DELETE /api/v1/auth/trusted-devices/{id}` | Bearer | — | `200` | 404 чужое/нет записи |

Пути refresh/revoke-token отмечены как не требующие access-token. Rate limiting
остаётся на уровне платформы/proxy; refresh-token имеет достаточную энтропию.

## Flutter Android

- `SessionService` хранит access/refresh-токены, id устройства, соль, итеративный
  SHA-256 verifier PIN и счётчик ошибок в `FlutterSecureStorage`.
- При старте с настроенным PIN роутер открывает `/pin`, не загружая кабинет.
- Четыре цифры проверяются локально; при успехе refresh API проверяет серверные
  права и выдаёт новую сессию. После пяти ошибок доверенные локальные данные
  стираются и требуется полный вход.
- После первого полного входа Android однократно предлагает PIN. «Не сейчас»
  оставляет настройку доступной в профиле.
- Профиль: включить/изменить/отключить PIN, показать доверенные устройства,
  отозвать выбранное. Обычный logout отзывает текущий refresh-token best effort.
- PIN не показывается на web/iOS и не попадает в логи/API.

## Адаптив и состояния

- PIN-экран: крупные цифры, индикатор четырёх позиций, удаление, полный вход.
- Ошибка PIN уменьшает число попыток; сетевая ошибка не уменьшает счётчик.
- При недействительном refresh приложение очищает доверенную сессию и показывает
  обычный вход. На узком/широком web профиль не получает PIN-элементы.

## Проверки

- Backend: создание, ротация, старый токен, срок, отзыв, чужой id, отключённые
  пользователь/школа, обязательная смена временного пароля.
- Flutter: настройка/повтор PIN, 1/5 ошибок, успешный refresh, offline, отключение,
  logout, отсутствие функции на web.
- Контракты полей и путей сверяются перед Timeweb; миграция идёт после `008`.
