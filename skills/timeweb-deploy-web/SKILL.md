# Timeweb: размещение готового Flutter Web

1. Прочитать `artifacts/timeweb-progress.md` и получить публичный API URL.
2. Записать одинаковый HTTPS API URL с `/api/v1` в `BASE_URL` и `BASE_URL_WEB` локального `init-app/assets/env/.env`.
3. Не запускать `flutter analyze`, `flutter build`, `make build-web-prod` и визуальную проверку приложения.
4. Попросить пользователя самостоятельно выполнить в `init-app/` команду `make build-web-prod` и сообщить, когда папка `init-app/build/web` готова.
5. После подтверждения пользователя только статически убедиться, что `build/web/index.html` существует и в подготовленном артефакте нет токенов, паролей или приватных адресов. URL API в клиентской сборке секретом не является.
6. Поскольку `build/` игнорируется, перед `git add -f init-app/build/web` показать состав артефакта и запросить подтверждение пользователя. Добавлять сборку только в предназначенную для Timeweb ветку.
7. Создать в App Platform приложение типа HTML/CSS/JS:

| Поле | Значение |
|---|---|
| Репозиторий и ветка | ветка с `build/web` |
| Имя App | латиницей, например `my-app-web` |
| Директория сборки | `/init-app/build/web` |
| Директория проекта | пусто |
| Команда сборки | пусто |

8. Дождаться деплоя и передать пользователю tech URL для ручной проверки загрузки, входа, вложенных маршрутов и narrow/wide-компоновки. При сообщённой CORS-ошибке добавить web-домен в `CORS_ORIGINS` API App.
9. Записать URL, факт передачи на ручную проверку и известные блокеры в `artifacts/timeweb-progress.md`.

После смены API или домена попросить пользователя заново выполнить `make build-web-prod`; Codex работает только с подтверждённой готовой папкой `build/web`.
