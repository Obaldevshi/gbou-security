# Локальный workflow Codex: mobile + web

## Основной маршрут

```text
$01-start
  → $02-import-idea
  → $03-define-features
  → ($03b-prioritize-mvp при необходимости)
  → $04-map-screens
  → $06-branding
  → $09-plan-features
  → $10-add-feature
  → $11-verify-mock (передача ручного чек-листа пользователю)
       ├─ пользователь сообщил об ошибке → $10b-fix-feature → $11-verify-mock
       ├─ ещё функции → $09-plan-features
       └─ очередь завершена → $13-check-api-timeweb
                                  └─ по явной команде → skills/timeweb-deploy/SKILL.md
```

Вспомогательные скиллы `$07-write-stories` и `$08-data-model` вызываются из планирования или реализации, когда поведение либо данные недостаточно определены.

Основной pipeline не требует локального backend, базы данных или полного локального стенда.

При реализации `$06-branding` читает `skills/helper-skill/design-flutter-ui/SKILL.md`, а `$10-add-feature` — Flutter и FastAPI architecture helpers из той же папки.

## Артефакты

Codex хранит рабочую память в `artifacts/`:

- `idea-brief.md` — структурированный импорт пользовательского файла с идеей;
- `feature-map.md` — состав MVP;
- `screens-map.md` — экраны, состояния, переходы и narrow/wide-компоновка;
- `user-stories.md` — неоднозначные сценарии;
- `data-model.md` — сущности и контракты;
- `app-config.md` — локальные команды и адреса без секретов;
- `features/_queue.md` — единая очередь функций;
- `features/<feature>.md` — план и результат одной функции;
- `api-timeweb-check.md` — соответствие Flutter/FastAPI и блокеры перед ручной загрузкой в Timeweb.
- `timeweb-progress.md` — этапы, публичные URL и блокеры фактического развёртывания.

## Правила выполнения

1. Реализовывать одну функцию за итерацию.
2. Перед изменением читать релевантный существующий код.
3. Синхронно менять контракты FastAPI и Flutter.
4. После генераторов проверять фактический diff.
5. Не запускать от имени Codex приложение, эмулятор, Chrome, визуальную проверку UI, `flutter analyze`, тесты и любые Flutter/Makefile-сборки без отдельной явной просьбы пользователя.
6. Перед ручной загрузкой в Timeweb сопоставлять маршруты, DTO, ошибки, авторизацию, env, миграции и команду запуска.
7. Переиспользовать Flutter-код mobile/web; narrow до `550` и wide выше `550` выбирать через `AppLayoutItemBuilder`.
8. Передавать пользователю ручной чек-лист для экранной клавиатуры и touch на телефоне, мыши, клавиатуры и изменения ширины окна в web; не утверждать, что UI проверен Codex.
9. Не выполнять загрузку в Timeweb и не изменять облачные ресурсы в рамках проверки соответствия.
10. В deploy-скиллах создавать платные ресурсы только после отдельного подтверждения пользователя и не сохранять секреты в git или артефакты.

## Готовность к ручной загрузке API

Работа завершена, когда:

- пользователь самостоятельно подтвердил запуск приложения на физическом телефоне;
- пользователь самостоятельно подтвердил запуск в Chrome и корректный narrow/wide;
- Flutter API services и DTO соответствуют маршрутам и схемам FastAPI;
- env, миграции, зависимости, health/readiness endpoints и команда запуска проверены статически;
- анализатор, тесты и сборки выполняются пользователем либо Codex только по отдельной явной просьбе;
- критические расхождения устранены;
- результат записан в `artifacts/api-timeweb-check.md`.

## Развёртывание после проверки

```text
skills/timeweb-deploy/SKILL.md
  → skills/timeweb-deploy-api/SKILL.md
  → skills/timeweb-deploy-web/SKILL.md
  → skills/timeweb-domains/SKILL.md
```

Flutter Web пользователь собирает локально, FastAPI собирается Timeweb по `init-api/Dockerfile`, база создаётся как managed PostgreSQL. Landing и мобильные магазины в этот поток не входят.
