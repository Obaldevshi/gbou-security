# Проектирование Flutter UI

1. Прочитать продуктовый сценарий, `artifacts/screens-map.md` и существующие экраны той же зоны.
2. Сначала определить визуальную иерархию: главный смысл, основное действие, вторичные действия и порядок чтения. Не добавлять декор без функции.
3. Использовать токены из `lib/app/theme/`: цвета через `Theme.of(context).colorScheme`, текст через `textTheme`, интервалы и размеры через `AppDimensions`.
4. Переиспользовать `ScrollShell`, `AuthScrollScaffold`, `GlobalButton`, `GlobalTextFormField` и общие компоненты до создания новых аналогов.
5. Не применять blur, backdrop-фильтры, тяжёлые тени и большие анимированные слои. Сохранять плавность на слабом телефоне.
6. Строить mobile-first компоновку. До 550 логических пикселей использовать `narrow`, выше — `wide` через `AppLayoutItemBuilder`.
7. На широком экране ограничивать контент: формы обычно до 720, страницы до 1200. Не растягивать текстовые строки и карточки на всю ширину.
8. Обеспечить touch-цели не меньше 48×48, видимый keyboard focus в web, понятные hover/pressed/disabled состояния и контрастный текст.
9. Для форм учитывать экранную клавиатуру, safe area и видимость активного поля. Использовать существующий `KeyboardInset`; не создавать конфликтующие вложенные scroll-контейнеры.
10. Предусмотреть loading, empty, error, offline, success и disabled состояния без скачков размеров интерфейса.
11. Выносить повторяемые или логически самостоятельные части в небольшие widgets. Не выполнять API-запросы и бизнес-правила внутри `build`.
12. Все пользовательские строки добавлять в ARB, изображения и SVG получать через generated assets, интерактивным элементам задавать tooltip/semantics при необходимости.
13. Не запускать приложение, эмулятор, Chrome, визуальную проверку UI, `flutter analyze`, тесты и сборки без отдельной явной просьбы пользователя.
14. В результате перечислить затронутые экраны и передать пользователю короткий ручной чек-лист: светлая/тёмная тема, narrow/wide, переполнение текста, клавиатура и нижний overscroll — только для изменённых частей.

Критерий результата: экран выглядит цельно, имеет один ясный визуальный акцент, не дублирует UI-kit и одинаково понятен при touch, мыши и клавиатуре.
