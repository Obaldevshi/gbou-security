# Передача mock-сценария на ручную проверку

1. Не запускать Flutter-приложение, эмулятор, Chrome, UI-тесты, `flutter analyze`, `flutter test` и сборки.
2. Кратко перечислить изменённые экраны, сценарии и состояния, которые пользователь должен проверить самостоятельно.
3. Передать команды для ручного запуска только как подсказку:
   - телефон: `flutter run -t lib/main_mock.dart -d <device-id>`;
   - web: `flutter run -t lib/main_mock.dart -d chrome --web-port 3000`.
4. В чек-лист включить основной сценарий, loading/empty/error, светлую и тёмную тему, narrow/wide, клавиатуру, нижний overscroll и переполнение текста — только если они затронуты изменением.
5. Не отмечать функцию проверенной от имени Codex. Зафиксировать, что визуальная и runtime-приёмка передана пользователю.
6. Если пользователь сообщает об ошибке, вызвать `$10b-fix-feature`; иначе продолжить с `$09-plan-features` или `$13-check-api-timeweb` по его указанию.
