# Проверка API перед Timeweb

1. Прочитать реализованные маршруты FastAPI, Pydantic-схемы, Flutter API services, DTO и карточки функций.
2. Составить таблицу соответствия: HTTP-метод, путь, path/query-параметры, тело запроса, успешный ответ и ошибки.
3. Проверить общий префикс API, Bearer-авторизацию, nullable-поля, enum, даты, пагинацию и имена JSON-полей.
4. Проверить, что Flutter обрабатывает фактические коды ответа и формат ошибок FastAPI.
5. Сопоставить настройки backend с `init-api/.env.example`: обязательные переменные должны быть перечислены без секретов.
6. Статически проверить зависимости, цепочку миграций, health/readiness endpoints, Dockerfile и команду запуска для Timeweb.
7. Запустить доступные генераторы, analyzer и тесты, которые не требуют поднятия базы данных или внешнего сервера.
8. Записать результат в `artifacts/api-timeweb-check.md`: таблицу контрактов, выполненные проверки, критические несоответствия и ручной чек-лист загрузки.
9. Не выполнять деплой, не создавать сервер и не изменять ресурсы Timeweb.
10. При критическом несоответствии вызвать `$10b-fix-feature` и повторить проверку; иначе отметить API готовым и предложить продолжить по `skills/timeweb-deploy/SKILL.md`.
