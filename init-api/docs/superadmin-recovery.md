# Непубличное восстановление пароля главного администратора

Восстановление выполняется оператором с доступом к терминалу backend и его БД.
Публичной страницы, HTTP-метода сброса и универсального второго пароля нет.
Ссылка на экране входа и выпуск кодов в профиле удалены. Обычная смена своего
пароля после входа сохранена.

## Команда

В терминале **backend-контейнера** Timeweb, где находится `/app`, выполните:

```sh
cd /app
python -m scripts.reset_superadmin_password --login superadmin
```

Если логин главного администратора изменён, укажите его вместо `superadmin`.
Это не команда для Raspberry Pi, Flutter-клиента или контейнера сайта.
Для самостоятельного Docker-хоста войдите через
`docker exec -it <имя-backend-контейнера> sh`, затем выполните команды выше.
Запускать нужно именно модулем (`-m`), а не `python scripts/...`, чтобы был доступен пакет `app`.

Команда использует штатные переменные окружения backend, включая `DATABASE_URL`.
Внешний доступ к PostgreSQL открывать не требуется. Отдельный публичный URL
или новый порт не нужен.

1. Проверьте указанный логин и нужное окружение (production / тестовое).
2. Дважды введите новый временный пароль. Ввод не отображается.
3. Минимум: восемь символов и одна русская или латинская буква.
   Из-за bcrypt допускается не более 72 байт UTF-8; кириллица занимает больше одного байта.
4. После сообщения об успехе войдите в приложение и установите постоянный пароль.

Пароль не передаётся аргументом команды, не сохраняется в переменных окружения,
не печатается и не попадает в историю shell. Нужен интерактивный терминал с TTY:
при отсутствии безопасного ввода команда прекращает работу.
Не используйте запись терминальной сессии при вводе секретов.

Скрипт работает только с существующим активным `super_admin`; он не создаёт
аккаунтов, не выдаёт другие роли и не включает отключённые учётные записи.
Сброс пароля, отзыв доверенных Android-устройств и запись события `CLI` в журнале выполняются одной транзакцией.
Несовпадение паролей или ошибка откатывает изменения.
Переустанавливать приложение или перезапускать backend после сброса не нужно.

Не оставляйте старые `SUPERADMIN_RESET_PASSWORD` / `SUPERADMIN_RESET_ID` в
окружении сервера: это прежний механизм восстановления при запуске. Для новой
команды они не нужны. Самостоятельно переменные production в этой правке не менялись.

Текущие короткие JWT-сессии действуют до истечения срока, но все длительные
доверенные Android-сессии выбранного администратора отзываются сразу. Не меняйте
общий `SECRET_KEY` без оценки последствий для всех пользователей.

## Выкладка и совместимость

Нужно обновить и backend, и Flutter web / Android. Одна лишь новая сборка клиента
скроет ссылку, но не отключит метод старого backend. После обновления backend
`POST /api/v1/auth/superadmin/recover` и `POST /api/v1/auth/superadmin/recovery-codes`
должны возвращать `404` и отсутствовать в OpenAPI. Старые клиенты восстановить
пароль этим способом больше не смогут. Миграции и исторические столбцы БД
сохранены: удаления пользовательских данных и новой миграции нет.

## Регрессия

- В web и Android на экране входа нет ссылки восстановления и нет доступной формы.
- В профиле нет создания кодов; обычная смена пароля и вход по-прежнему работают.
- Оба бывших HTTP-маршрута недоступны даже при прямом запросе.
- На тестовой БД: корректный CLI-сброс меняет пароль только выбранного суперадмина,
  отзывает доверенные устройства и требует смены временного пароля при входе.
- Неизвестный логин, роль учителя/охранника/админа школы, отключённая запись,
  короткий пароль, пароль без букв, несовпадение повторного ввода и отсутствие TTY
  не меняют записи.
- Ошибка записи журнала / commit откатывает сброс; секреты не выводятся.

Точечные проверки для отдельного запуска из `init-api` с тестовой конфигурацией:

```sh
python -m pytest tests/test_superadmin_recovery_cli.py
```
