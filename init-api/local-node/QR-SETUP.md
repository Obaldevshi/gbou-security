# Подключение новой Raspberry с телефона

Статус: исходники L07. До публикации API/web и включения
`DEVICE_PAIRING_ENABLED=true` QR-регистрация на production недоступна.
Работающую Raspberry2036 этот комплект НЕ обновляет/не регистрирует повторно.

## Что получится

1. Новая Raspberry показывает QR и отдельный шестизначный код.
2. Администратор сканирует его штатной камерой телефона. Откроется
   `https://gbousecurity.ru/#/connect/<случайный UUID>`.
3. Входит центральной учётной записью администратора. Это отдельная сессия
   на5минут; ученики и заявки через неё недоступны. Временный пароль сначала
   нужно сменить здесь же. Это пароль центральной записи, который далее
   передаётся узлу существующей синхронизацией администраторов.
4. Выбирает школу (школьному администратору доступна только своя), активный
   корпус, роль и вводит код с экрана Raspberry. Проверяет итог и подтверждает.
5. Устройство само забирает настройки. QR живёт10минут, неверный код допускает
   5попыток; затем показывается новый QR. Старый QR использовать нельзя.

QR не содержит паролей, VPN private key или машинного токена. Poll proof
остаётся в root-only файле устройства, доставка настроек — HTTPS. В браузер
попадают только QR/код/публичный адрес/статус. Подтверждённые credentials
перестают выдаваться после ACK. Не фотографируйте код вместе с QR для
передачи незнакомым людям: подключайте только физически контролируемый узел.

## Установка один раз на НОВОЕ устройство

Потребуются интернет, Python3, WireGuard tools и уже установленный пакет
киоска, если устройство будет дочерним. Обычную Raspberry Pi OS и Wi-Fi
настраивают до этого. Команды выполняются через SSH **на Linux Raspberry**,
не в локальном PowerShell. Из каталога `local-node`:

```sh
sudo sh ./install-pairing.sh
```

Открыть на экране Raspberry `http://127.0.0.1:8766/`. Обновлённый киоск
также показывает кнопку «Подключить Raspberry через QR» на странице входа,
но только если setup-service установлен и ещё нет регистрации/БД/туннеля.
После настройки Wi-Fi можно вернуться к QR. Устанавливать этот пакет заново
при каждом добавлении корпуса не требуется. Публичный вход на8766 НЕ открыт.

Установщик откажет при существующем `device.json`, рабочей SQLite или
`/etc/wireguard/gbou-wg.conf`. Не удаляйте их, чтобы обойти защиту. Не клонируйте
identity/секреты с SD другого устройства. Не запускайте этот установщик на
текущем школьном сервере2036.

## Главное и дочернее

**Главное:** одно на школу, обслуживает все корпуса, хранит единственную
рабочую SQLite. Назначенный корпус — расположение устройства, не разделение
школьной базы на независимые writers. QR регистрирует его как `pending`,
сохраняет кандидата WireGuard в `/etc/gbou-device/gbou-wg.conf`, но НЕ включает
туннель/API/Caddy, НЕ переносит БД и НЕ меняет публичный маршрут. Дальше нужны
локальный API, сеть/HTTPS, резервирование и проверенное восстановление;
следовать `CUTOVER.md`. Только после физической остановки/изоляции прежнего
writer администратор может отдельно нажать «Активировать» и подтвердить
обе проверки. Сервер проверяет generation (CAS); старый адрес сохраняется.

**Дочернее:** подключается только после активного управляемого главного узла.
SQLite/sync-secret/VPN-конфиг не выдаются. Таймер каждые30сек проверяет
регистрацию, HTTPS/ready школы и отсутствие локальной БД/API. После успеха
меняет только адрес существующего киоска на устойчивый школьный HTTPS и
перезапускает киоск; исходный конфиг резервируется. Нужен обычный аккаунт
охранника с нужным корпусом — регистрация машины не даёт доступа к детям.
При недоступности школьного адреса ждёт, НЕ возвращается к облачной базе.
Отзыв регистрации сам по себе не отзывает сессию охранника.

Существующая2036 пока unmanaged legacy: её адрес и ключ сохраняются. Перед
добавлением к ней дочерних устройств через новый реестр нужно отдельно
спланировать безопасное adoption текущего primary. Не активировать вместо
него пустую новую Pi и не отзывать старый sync key ради демонстрации QR.

## Хранение и обслуживание

- Setup-agent: `gbou-device-setup.service`, loopback8766, read/write только
  `/etc/gbou-device`; без запуска инфраструктуры. Файлы0700/0600.
- Дочерний helper: `gbou-device-terminal.timer/service`; root oneshot без
  HTTP-интерфейса, фиксированный скрипт, отдельные проверки перед записью.
- `device.json` не содержит token; токен — `device.token`, WG key — отдельно.
- Не удалять `pairing-state.json`: нужен для восстановления после потери
  HTTP-ответа/ACK. До подтверждения запрос можно обновить по истечении TTL.
- Если назначение подтверждено, но устройство было выключено более10минут
  до получения credentials, автоматическое переназначение запрещено.
  Нужна проверка записи администратором; не создавайте новую identity вслепую.
- После полного ввода главного узла setup-service можно остановить/отключить.
  Отдельной работающей копии БД у setup-agent нет.

## Ручная приёмка (отдельная тестовая Raspberry)

- Телефон: QR → логин → при необходимости смена временного пароля → свой
  корпус/роль/код → результат. Второй confirm409; старый QR404; чужая школа404.
- Ошибочный код, истечение10мин, потеря интернета и перезапуск setup-agent.
  Нет токенов/паролей в URL, HTML, `/state`, stdout и admin-списке.
- Дочернее без primary не разрешено; после активного primary киоск
  автоматически подключается. При HTTPS503 остаётся в ожидании.
- Primary после QR остаётся pending; ничего не пишет в школьную БД.
- Узкий/широкий экран, светлая/тёмная тема, клавиатура, длинный корпус,
  прокрутка до последней кнопки, loading/empty/error. Новая страница вне
  нижней школьной навигации: кнопки не перекрываются ею.
- Mock: из `init-app`: `flutter run -t lib/main_mock.dart -d chrome --web-port 3000`,
  затем `http://localhost:3000/#/connect/demo`; демо-код123456, данные фиктивные.
  Телефон: `flutter run -t lib/main_mock.dart -d <device-id>` (маршрут/connect).
  APK AppLinks/встроенный QR-сканер не добавлены: используется камера→браузер.

Это не регламент аппаратной миграции. Реальная проверка камеры/второй Pi и
публикация выполняются отдельно; текущий writer и DNS не меняются установкой
исходников на компьютере разработчика.
