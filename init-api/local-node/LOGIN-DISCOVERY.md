# Автоматическое определение школы по логину

## Состояние

Код подготовлен 19.10.2026, production в этой итерации НЕ менялся. Нужна
согласованная публикация центра, школьного API/sync, центрального web и APK.
Перенос SQLite, повторная привязка и новые ключи устройств НЕ нужны.

## Что выходит с Raspberry

Только SHA-256 от `gbou-login-directory-v1:` + trim/lower логина активного
сотрудника своей школы. Центр дополнительно HMAC-ирует этот digest отдельным
секретом. Сохраняются HMAC-тег, school_id, generation, expires_at и технические
timestamps. Исходный логин, телефон, ФИО, пароль и хеш пароля не входят в снимок.
Псевдонимизация не равна анонимности; публичный поиск даёт возможность проверки
предположений об идентификаторах. Нельзя обещать невозможность перебора.

## Порядок включения

1. Сохранить штатные зашифрованные резервные копии. Не подменять существующий
   writer, данные, адрес, WireGuard, node.token или регистрацию устройства.
2. Опубликовать совместимый центральный backend, применить новую Alembic 015.
   Пока флаг выключен, обычные школьные входы/синхронизация не меняются.
3. В центральном API задать `LOGIN_DIRECTORY_ENABLED=true` и отдельный
   `LOGIN_DIRECTORY_PEPPER` — минимум 32 случайных байта, не SECRET_KEY и не
   токен устройства. Создать его через защищённый канал и сохранить в секретном
   хранилище; не помещать значение в Git, сообщения, команды с журналированием
   или публичные переменные frontend. Секрет нужен ТОЛЬКО центру, не Pi/APK.
   `SCHOOL_DEVICES_ENABLED` также должен быть включён.
4. Обновить код API и scripts на Pi без пересоздания базы; задать только
   `LOGIN_DIRECTORY_ENABLED=true` в её API env. Текущий scoped token главной
   Raspberry уже подходит: сервер всё равно проверяет primary ownership и CAS
   generation. Дочерняя/старая/отозванная Raspberry публиковать указатели не может.
5. Перезапуск API нужен для точного CORS origin `https://gbousecurity.ru`.
   Не добавлять wildcard, отключение TLS-проверки или доверие любому X-Forwarded-For.
6. Запустить штатный `python -m scripts.node_config sync` в сервисном окружении
   Pi. Теперь после успешного config sync он публикует указатель. Либо отдельно
   `python -m scripts.login_directory`. Команды не печатают логины и credentials.
   Проверить только итог success/количество; не выводить запросы или полный SQL.
7. Проверить известный синтетический login в изолированной проверке; реальные
   входы выполняет пользователь. Не рассылать рабочие пароли в curl/журналы.
8. Только после первого успешного snapshot собрать/опубликовать новые central
   web (GBOU_CLOUD_ONLY=true) и APK. Школьный web (GBOU_LOCAL_MODE=true) продолжает
   входить на свой origin напрямую без зависимости от центрального указателя.

## Поведение

- В новом приложении выбран автоматический режим. При обновлении старое ручное
  подключение сохраняется: включение авто доступно в настройках подключения.
- Адрес сохраняется только после успешной проверки пароля на школьном сервере
  и проверки school_id/роли. Неверный пароль не меняет endpoint/PIN/сессию.
- Главный администратор явно выбирает центральный сервер в настройках; его
  пароль никогда не передаётся поиском в другие школы.
- На сервере нет поиска по паролю и fan-out к нескольким Raspberry. При дубликате
  или неизвестном логине — одинаковая ошибка и предложение ручного адреса.
- Если ранее подтверждённый логин внезапно указывает на ДРУГУЮ школу, пароль не
  отправляется: требуется проверить адрес и выполнить явное подключение.
- Для того же подтверждённого логина при сетевом тайм-ауте/отсутствии сети до
  справочника допустим сохранённый адрес; отсутствие/конфликт/ошибка сертификата
  не превращаются в поиск по другим серверам. Проверка пароля всё равно онлайн
  на Pi, а не автономная авторизация из кэша.
- Обновление снимка раз в 5 минут. Отключение/удаление/смена логина исключают
  старый digest следующим успешным snapshot. Пароль и блокировка проверяются
  Pi немедленно, поэтому старый указатель не даёт доступа к удалённому аккаунту.
- TTL 24 часа; истёкшие записи не участвуют в поиске, удаляются при следующем
  успешном snapshot любой школы. При остановке всего сервиса физическая очистка
  откладывается; не обещать немедленное стирание резервных копий.
- Доверие первому указателю основано на утверждённом оператором реестре primary.
  HMAC защищает сохранённые теги, но не доказывает криптографически, что новый
  администратор школы вправе заявить произвольный телефонный логин. Первичная
  регистрация устройства должна оставаться контролируемой, а не публичной.

## Лимиты и отказоустойчивость

До 10000 уникальных указателей в snapshot. Размер тела: resolve 2 КиБ,
snapshot 1 МиБ, в том числе при chunked-передаче. Встроенный лимит поиска —
12 запросов/мин для пары сетевой клиент+digest и 1200/мин на сетевого клиента.
Он не меняет школьную per-login защиту и не блокирует сам /auth/login школы.
IP/бuckets живут только в bounded оперативной памяти (4096 на limiter).
При нескольких workers/репликах нужен общий ingress limiter; нельзя выдавать
per-process ограничение за распределённую защиту. За прокси проверить корректную
настройку trusted forwarded headers, иначе клиентом может считаться весь прокси.

Сбой публикации индекса не откатывает уже успешно выполненный config sync;
следующий timer повторит публикацию. Старый индекс истекает по TTL. Для
ротации pepper требуется повторный snapshot всех школ; до этого использовать
прежнее ручное подключение. Секрет не ротировать без окна совместимого обновления.

Откат: вернуть прежние web/APK или явный адрес, выключить флаги. Не удалять
пользователей/школьную SQLite, не восстанавливать старый writer. Таблица индекса
не является базой аккаунтов и не используется для проверки паролей.

## Приёмка

Изолированные unit/HTTP/SQLite/PIN-проверки описаны в L14. Перед публикацией
нужна отдельная реальная проверка нового APK и браузера: ввод логина/пароля,
роль/корпус, запросы после входа идут на Pi, перезапуск приложения, PIN, ручной
режим, недоступность справочника. В browser DevTools проверить fetch redirect:error,
credentials:omit и разрешённый CORS. Не записывать пароли и тела auth-запросов.
Визуальная приёмка и тест веб-адаптера в настоящем браузере пока НЕ выполнены.
