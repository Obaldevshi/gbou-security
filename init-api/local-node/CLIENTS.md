# Подключение телефонов и компьютеров к школьному серверу

Raspberry установлена 18.10.2026; публичный CA сохранён в комплекте подключения.
Локальный сервер не публикуется через проброс портов домашнего роутера.
Для доступа из дома и мобильных сетей подготовлен отдельный адрес
`https://school-2036.gbousecurity.ru`: HTTPS через Timeweb TCP-шлюз и закрытый
WireGuard до Pi. Учителям не нужны VPN-приложения или профили. Сертификат
публично доверенный, импорт школьного CA для этого адреса не нужен.
На 18.10.2026 снаружи пока только сообщение о подготовке (HTTP 503):
**не переводить рабочие устройства до объявления финального переключения**.

Резервный прямой LAN-доступ требует общей сети с Raspberry. Гостевой Wi-Fi
с изоляцией клиентов обычно для этого не подходит. Он использует отдельный
локальный CA и не заменяет проверку публичного HTTPS.

## Android 1.4.0

1. На странице входа нажать **Подключение к школе**.
2. После переключения ввести `https://school-2036.gbousecurity.ru`.
   Не импортировать CA при использовании этого публичного адреса.
   Для резервного LAN-подключения адрес может быть `https://gbousecurity.local`.
   Если mDNS в сети недоступен, администратор настраивает обычное локальное DNS-имя
   и сертификат для этого имени; нельзя просто заменить адрес на произвольный IP.
   На установленном узле также проверяется HTTPS по текущему внутреннему IPv4
   с отдельным IP SAN. Настроить только адрес, реально принадлежащий Raspberry:
   `sudo sh local-node/configure-lan-address.sh <IPv4>`. При смене школьной
   сети повторить настройку и закрепить адрес в DHCP. Прежний IP не переносится
   автоматически между школой и домом.
3. Только для резервного LAN Caddy `tls internal` импортировать **публичный корневой сертификат** школы
   (`root.crt` в формате PEM). Закрытый ключ никогда не распространять.
4. Сверить SHA-256 с отпечатком, полученным лично от администратора или из
   защищённой инструкции, отметить совпадение и сохранить.
5. Войти школьным логином. После смены подключения прежний вход и PIN удалены;
   PIN можно настроить заново после полноценного входа.

При обычном публично доверенном HTTPS-сертификате импорт не нужен. Для главного
администратора в окне есть возврат к центральному серверу. При недоступности
школьного сервера приложение не переключается в облако и не отправляет туда
учётные данные. HTTP, дополнительные пути, пароль в URL и перенаправления API
не разрешены. Сертификат проверяется с учётом имени сервера и срока действия.

Приложение доверяет школьному CA только для выбранного подключения, а не
устанавливает его системно для остальных приложений телефона. Реальная
проверка на Android и сертификате Raspberry ещё обязательна.

## Получение корневого сертификата на Raspberry

При стандартном пакетном Caddy публичный сертификат обычно находится здесь:

```sh
sudo find /var/lib/caddy -path '*/pki/authorities/local/root.crt' -type f
```

Передавать именно найденный `.crt`, не каталог CA целиком и не `root.key`.
Сверить отпечаток DER-сертификата:

```sh
openssl x509 -in /точный/путь/root.crt -outform DER | sha256sum
```

Файл сертификата и отпечаток передавать по доверенному каналу, отдельно от
пароля пользователя. Не загружать сертификат с неизвестной страницы и не
соглашаться на предупреждение без сверки.

## Браузер

После переключения открыть `https://school-2036.gbousecurity.ru` с телефона
или компьютера. Проверка публичного сертификата штатная, без установки CA.
Для резервного LAN-адреса доверие к корневому сертификату
настраивается средствами ОС/браузера школьным администратором; Android-импорт
в приложение на браузер не распространяется. Не обходить предупреждения TLS.
Школьная web-сборка использует `/api/v1` того же адреса, включая локальное DNS-имя.

Для компьютеров администратора желательно управляемое распространение
сертификата и ограничение сети. Публичный `gbousecurity.ru` после переноса
предназначен для главного администратора и информационной страницы.

## Основания технических решений

Ни рабочая SD-карта, ни USB-копия не должны передаваться посторонним.
Шифрование USB-копий не шифрует саму рабочую SD-карту: её физическую защиту,
шифрование диска и регламент обработки данных проверяем отдельно.
